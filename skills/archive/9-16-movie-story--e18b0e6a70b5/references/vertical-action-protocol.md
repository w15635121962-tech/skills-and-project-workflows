# 竖屏动作协议 (Vertical Action Protocol)

> 专为 9:16 竖屏画幅重构的动作场景协议。原版 16:9 动作场景直接用于竖屏会导致主体偏移、构图失衡、平台裁剪。

---

## 一、竖屏动作场景核心法则

### 1.1 垂直构图优先级
| 横屏 16:9 | 竖屏 9:16 | 原因 |
|------------|------------|------|
| 左右平衡 | 上下平衡 | 手机握持方向 |
| 地面在画面下沿 | 地面在底部 20%（互动区） | 避免 UI 遮挡 |
| 天空在画面上沿 | 天空在顶部 10%（标题区） | 避免字幕遮挡 |
| 动作横向展开 | 动作垂直展开 | 竖屏空间利用 |

### 1.2 动作安全区（竖屏专用）

```
┌─────────────────┐  ← 顶部 10%：标题/字幕区（避免动作）
│  安全区          │
├─────────────────┤
│  核心动作区      │  ← 动作必须在此区域 (10-80%)
│  (人物/道具)    │
├─────────────────┤
│  互动区          │  ← 底部 20%：点赞/评论/转发（避免动作）
└─────────────────┘
```

### 1.3 动作设计原则（竖屏版）

1. **垂直动作优先**：跳跃、跌倒、起身等垂直动作比水平动作更适合竖屏
2. **面部始终可见**：眼睛必须在 1/3 处，不能出画
3. **底部 20% 留空**：避免与平台 UI 重叠
4. **单手操作适配**：右侧 15% 避免重要动作（抖音/ Shorts）

## 二、竖屏动作场景覆盖策略

### 2.1 原版 vs 竖屏版对比

| 镜头类型 | 横屏 16:9 | 竖屏 9:16 |
|---------|-----------|-----------|
| Master Shot | 全景建立空间 | 全身景，脚贴底，头顶留 15% |
| Action Wide | 广角动作 | 垂直广角，从脚到头 |
| Close-Up (动作) | 手部/道具特写 | 竖直构图，避免横放 |
| Follow Shot | 侧面跟拍 | 前跟/后跟，面部居中 |
| Impact Shot | 冲击帧 | 垂直冲击（从上到下） |

### 2.2 竖屏动作最小覆盖（3 镜方案）

```
镜1: 全身景（垂直构图，脚贴底）→ 建立动作空间
镜2: 腰部以上（眼睛在 1/3）→ 动作准备
镜3: 特写（手部/面部）→ 动作高潮
```
> 比横屏少 2-3 个镜头，因为竖屏单镜信息密度更高

### 2.3 竖屏动作运镜（专用）

| 运镜 | 横屏 | 竖屏 | 提示词关键词 |
|------|------|------|-------------|
| 垂直推进 | 推镜头 | **垂直推进**（从脚到脸） | `vertical push-in, from feet to face` |
| 垂直拉远 | 拉镜头 | **垂直拉远**（从脸到脚） | `vertical pull-out, from face to feet` |
| 上摇 | 抬头拍 | **上摇**（从脚到脸） | `tilt up from feet to face` |
| 下摇 | 低头拍 | **下摇**（从脸到脚） | `tilt down from face to feet` |
| 斜向跟随 | 侧面跟 | **斜向跟随**（45°） | `diagonal follow shot, 45° angle` |
| 垂直环绕 | 环绕 | **垂直环绕**（椭圆） | `vertical orbit, elliptical path` |

## 三、竖屏动作提示词模板

### 3.1 基础模板

```
{SUBJECT}, {ACTION}, {VERTICAL_POSITON: 眼睛在1/3处},
{ENVIRONMENT}, {LIGHTING},
{TECHNICAL: --ar 9:16, vertical framing, 9:16 aspect ratio},
{TEXTURE: 手机屏优化, OLED optimized},
--no {负面词: horizontal composition, face cropped}
```

### 3.2 动作场景专用提示词

```
{人物}, {动作}, 眼睛在画面上1/3处,
{环境}, {光影}, 动作模糊,
垂直构图, --ar 9:16, vertical framing,
手机屏显示优化, 高对比度,
--no 水平构图, 人脸裁剪, 底部杂乱
```

### 3.3 各平台动作提示词

| 平台 | 提示词格式 | 示例 |
|------|-----------|------|
| Midjourney | `{prompt} --ar 9:16 --style raw` | `王勃 拔剑 竖屏 --ar 9:16` |
| Seedance | `参考图中人物，{动作}, 竖屏构图, --ar 9:16` | `参考图中人物，拔剑，竖屏构图，--ar 9:16` |
| Kling 3 | `{"prompt": "{prompt}", "camera_movement": "vertical"}` | `{"prompt": "王勃拔剑", "camera_movement": "vertical_push_in"}` |
| Runway | `{prompt}, vertical composition, 9:16` | `王勃拔剑, vertical composition, 9:16` |
| 即梦 | `{主体}, {动作}, 竖屏构图, --ar 9:16` | `王勃, 拔剑, 竖屏构图, --ar 9:16` |

## 五、竖屏动作质量检测

### 5.1 动作镜头必检项

- [ ] 眼睛是否在 1/3 处？
- [ ] 头顶是否留白 15%？
- [ ] 底部 20% 是否为空（或仅有字幕）？
- [ ] 动作是否垂直展开（不是水平）？
- [ ] 提示词是否包含 `--ar 9:16` 和 `vertical framing`？
- [ ] 右侧 15% 是否避免重要动作（抖音/ Shorts）？
- [ ] 是否包含竖屏负面词（`--no horizontal composition, face cropped`）？

### 5.2 动作流畅度检测（竖屏专属）

| 检测项 | 横屏标准 | 竖屏标准 | 工具 |
|--------|---------|---------|------|
| 动作方向 | 任何 | **垂直方向优先** | 手动检查 |
| 面部可见性 | 任何 | **眼睛必须在 1/3 处** | 手动检查 |
| 平台 UI 遮挡 | 无 | **底部 20% 留空** | 平台预览 |
| 单手操作适配 | 无 | **右侧 15% 避免重要动作** | 平台预览 |

### 5.3 常见问题与修正

| 问题 | 原因 | 修正提示词 |
|------|------|-----------|
| 眼睛位置错误 | 未指定垂直位置 | `eyes at upper 1/3, vertical rule of thirds` |
| 人脸出画 | 推进时未锁定眼睛 | `face always visible, headroom 15%` |
| 动作水平展开 | 横屏思维 | `vertical action, up-down movement` |
| 平台 UI 遮挡 | 底部 20% 有动作 | `bottom frame empty, space for UI` |
| 右侧重要动作被遮挡 | 抖音/ Shorts 右侧 UI | `action on left side, right 15% empty` |

## 六、竖屏动作场景案例

### 6.1 案例：王勃起身（竖屏重构）

**横屏原版**：
```
镜001：王勃（全景），起身，镜头推进，
阴雨夜，闪电，冷蓝调，
--ar 16:9, cinematic lighting
```

**竖屏重构版**：
```
镜001：王勃（全身景），起身，眼睛在画面上1/3处，
垂直推进镜头，从脚推到腰部，
阴雨夜，闪电，冷蓝调，画面底部留互动区，
--ar 9:16, vertical framing, 9:16 aspect ratio,
手机屏显示优化, 高对比度,
--no 水平构图, 人脸裁剪, 底部杂乱
```

### 6.2 案例：剑刃出鞘（竖屏重构）

**横屏原版**：
```
镜002：剑刃特写，出鞘，金属反光，
侧光，冷色调，
--ar 16:9, macro photography
```

**竖屏重构版**：
```
镜002：剑刃特写（竖直构图），出鞘，金属反光，
眼睛在画面上1/3处（如果有人物），
侧光（垂直方向），冷色调，
--ar 9:16, vertical framing, macro photography,
手机屏显示优化, 高对比度,
--no 水平构图, 人脸裁剪, 底部杂乱
```

### 6.3 案例：雨水下落（竖屏专属）

**竖屏专属动作**：雨水从画面上方向下落到画面下方，完美利用竖屏空间。

```
镜003：雨水特写，从画面上方下落到底部，
垂直构图，慢动作，
阴雨夜，闪电，冷蓝调，
--ar 9:16, vertical framing, slow motion,
手机屏显示优化, 高对比度,
--no 水平构图, 人脸裁剪
```

## 八、竖屏动作场景质量自检

### 8.1 六轮自检（竖屏动作版）

1. **剧本覆盖度**：动作场景是否 100% 覆盖剧本？
2. **视觉一致性**：眼睛是否在 1/3 处？顶部留白 15%？
3. **镜头语法**：运镜是否有垂直分量（不是纯水平）？
4. **AI 提示词质量**：是否包含 `--ar 9:16` 和 `vertical framing`？
5. **Coverage & Spatial**：动作覆盖是否 ≥3 个镜头？
6. **整体验收**：在手机上播放是否清晰？动作是否流畅？

### 8.2 动作场景专项检查

- [ ] 动作是否垂直展开（不是水平）？
- [ ] 眼睛是否在 1/3 处（如果有人物）？
- [ ] 底部 20% 是否为空（或仅有字幕）？
- [ ] 右侧 15% 是否避免重要动作（抖音/ Shorts）？
- [ ] 提示词是否包含 `--ar 9:16` 和 `vertical framing`？
- [ ] 是否包含竖屏负面词（`--no horizontal composition, face cropped`）？
