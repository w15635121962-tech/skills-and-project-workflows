> 加载时机：任何一次完整分镜任务（必读）。含单集输出骨架、自检表、新对话提示词。

## 2. 自检清单

每次输出前必须自检：

| 检查项 | 标准 |
|---|---|
| S组时长 | 每组不超过 15 秒 |
| 台词时长 | 长句不塞进短时长 |
| 台词画面绑定 | 每句台词都有对应画面或反应 |
| 情绪准确 | 人物状态符合剧情，不乱哭不乱崩 |
| 景别合理 | 远景管心境，全景管故事，中景管调度，近景管台词，特写管情绪 |
| 组间衔接 | 上组尾帧能接下组首镜 |
| 人脸一致 | 同组主脸明确，避免重复人物 |
| 防穿帮 | 没有容易生成错误的背景人、重复人、奇怪光效 |
| SD提示词 | Positive / Negative 都完整 |
| 禁止词 | 不出现月纹、眼睛冒光、身体发光等穿帮描述 |
| Word输出 | 生成可打开 Word 文档 |

**通过声明格式：**

```
═══════════════════════════════════════════
分镜: 通过
═══════════════════════════════════════════
S组: [N/N] ✓ · 全部 ≤15s ✓
台词绑定: [N/N] ✓ · 气口: 通过
情绪: 通过 · 无错位
景别: 通过
衔接: 通过 · 尾帧断层: 0
防穿帮: 通过 · 重复人物风险: 0
SD提示词: Positive [N/N] · Negative [N/N]
禁止词: 0
总时长: ___s · 镜头: ___
可进入生产。
═══════════════════════════════════════════
```

未通过项必须先修复，再重新声明。

## 2.4 台词来源标注（当原稿不在工作区时，必做）

多集长稿任务里经常出现这种情况：用户一次性粘了 8 集剧本，但做完前 5 集后，**后 3 集的原文已经不在工作区**（长上下文中段被截断）。
这时**绝对不要静默补写台词**——补写的措辞会和原稿对不上，后期配音直接返工。

处理规程：

1. 仍按剧情意图把台词写出来（保证分镜能落地、时长能算）。
2. 在该集分片的**标题下方第一行**加一条可见横幅：

   ```md
   > 台词提示：本集英文台词均为按剧本意图补写，**上线前请与原稿逐句核对**（清单见文末自检「台词校对清单」）
   ```

3. 在 `part-99-selfcheck.md` 里开一节 **台词校对清单**，按集分表，逐句列出：`序号 | 角色 | 台词 | 备注`。
4. 通过声明后追加一行保留项，写明需核对的句数：

   ```
   **唯一保留项**：EPxx–EPxx 补写台词（NN 句）需与原稿逐句核对——见第 N 节清单。核对完成即可锁定 v02。
   ```

判定标准：**逐句取自原稿的集，不标注；非逐句取自原稿的集，逐句标注。** 宁可多标，不可漏标。

## 2.5 Word 导出（必做，且不要依赖 pandoc）

自检清单里「Word输出」是硬项。本机实测：**pandoc / soffice / libreoffice 均不可用**，
唯一可靠路径是 `python-docx` + 本技能自带的 `scripts/md2docx.py`。

**分片命名约定**（多集任务必须遵守，否则拼接会漏文件）：

```
part-00-front.md          前言：情绪主线 + 挂载资产 + 人脸锁定
part-01-ep31.md           第 1 集正文（每集一个文件）
part-02-ep32.md
...
part-NN-epXX.md           第 N 集正文
part-99-selfcheck.md      自检与交付说明（永远放最后，用 99 保证排序在正文之后）
```

**单集任务**（只有一集）用 `part-01-*.md` + `part-05-selfcheck.md`；
**多集任务**用 `part-0N-epXX.md` + `part-99-selfcheck.md`。

```bash
# 1) 先把分片 Markdown 合成一份完整 md（不要一边写一边导）
cd <输出目录>
OUT="《剧名》EPxx-EPxx 单集分镜 SD2挂载版 v01.md"

# 单集：
{ cat part-00-front.md; echo; \
  sed -E 's/^# EP/## EP/' part-01-*.md; echo; \
  cat part-05-selfcheck.md; } > "$OUT"

# 多集：把每一集的分片都列进去（用 glob 展开，别手写漏掉）
{ cat part-00-front.md; echo; \
  sed -E 's/^# EP/## EP/' part-01-ep*.md part-02-ep*.md part-03-ep*.md part-04-ep*.md \
                              part-05-ep*.md part-06-ep*.md part-07-ep*.md part-08-ep*.md; echo; \
  cat part-99-selfcheck.md; } > "$OUT"

# 顺手把 S 组标题降一级，层级为 文档(1) → 集(2) → S组(3)
sed -i '' -E 's/^## (S[0-9]+[AB]?)｜/### \1｜/' "$OUT"

# 2) 转换
/Users/zc/.workbuddy/binaries/python/envs/default/bin/python \
  ~/.workbuddy/skills/short-drama-sgroup-storyboard/scripts/md2docx.py \
  "$OUT" "${OUT%.md}.docx"
```

**拼完先自检三个数**（比只看文件大小可靠得多）：

```bash
wc -l "$OUT"                      # 行数应上千
grep -c '^### S' "$OUT"           # 必须等于 S 组总数
grep -c '^## EP' "$OUT"           # 必须等于集数
```

`md2docx.py` 已支持：标题（1–6 级）、段落、引用块、表格（含表头底色与网格线）、
代码块（灰底 + 左侧色条，用于挂载卡与正/反向提示词）、水平线、`**加粗**`、`` `行内代码` ``、无序列表。

**导出后必须回读校验**，不能只看文件大小：

```python
from docx import Document
import re
d = Document("xxx.docx")
# 权威口径：直接数 Markdown 的表格分隔行，再和 docx 的表格数比对
md = open("xxx.md", encoding="utf-8").read()
md_tables = len(re.findall(r'^\|---', md, re.M))
assert len(d.tables) == md_tables, f"{len(d.tables)} != {md_tables}"
print(len(d.paragraphs), len(d.tables))
```

验收口径（通用，单集／多集都适用）：

**表格数 = S 组数 + 前言表数 + 自检文件里的表数**

- 前言固定 3 张表：情绪主线表、挂载资产表、人脸锁定表
- 自检文件至少 9 张表：分集汇总、一致性核查、无台词组、长台词拆镜、组间衔接链、台词校对表（按集分）、自检清单
- 例（EP31–EP38 实测）：`90 组 + 3 前言 + 9 自检 = 102` 张表，段落数 1450

段落数应在数百到数千量级。低于这个数说明某个分片没拼进去。

## 3. 新对话使用提示词

新建对话时可直接复制下面这段：

```md
请严格按照《短剧分镜经验总结｜新对话使用版》执行。

你是成熟短剧导演，不只是整理剧本，而是要根据爆款短剧逻辑做分镜：情绪优先、故事因果清楚、
台词画面绑定、每个 S 组 15 秒以内、每句台词有足够气口、每个镜头有景别和运镜、
每组有 SD2.0 挂载提示词，并做自检。

景别规则：
远景管 OS 和心境；全景管故事发展；中景管调度和逻辑；近景管对峙和台词；特写管表情、手部和情绪。

不要出现月纹、眼睛冒光、瞳孔发光、身体发光、莫名其妙空镜、无意义白布、重复人物、背景乱生人。

如果台词太长，不要强塞短时长，要拆镜、切听者反应、给气口。
如果画面看不懂，要用证据链、人物反应、道具锚点和组间衔接重构。
如果 SD 容易穿帮，要改成单人近景/特写，一镜只保留一个清晰人物脸。

输出：资产清单 + 完整分镜 MD + SD2.0 Positive/Negative Prompt + 自检 + Word 文件。
```

## 4. 关键判断标准（交付前最后一问）

1. 观众能不能一眼看懂发生了什么。
2. 情绪是不是跟人物此刻心理一致。
3. 台词是不是有对应画面。
4. 镜头能不能剪。
5. SD2.0 会不会乱生人、乱生道具、乱生光效。
6. 每个 S 组是不是都有明确起点、变化和尾帧。

**最终标准：画面清楚、情绪准确、台词能说完、剪辑能接上、生成不穿帮。**
